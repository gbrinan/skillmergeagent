# 자료 없이 시작하는 문답 예시

아래는 수정한 askflow를 작성 에이전트가 적용한 수동 문답 시뮬레이션이다. 사용자 발화는 합성 입력이며 실제 고객 인터뷰나 독립 성능 평가가 아니다.

## 1. 업무만 정하기

사용자: 반복 업무를 워크플로우로 만들고 싶어. 가진 스킬이나 파일은 없어.

에이전트: 자료 없이 업무 설명부터 시작하겠습니다. 가장 먼저 줄이고 싶은 반복 업무는 무엇인가요?

## 2. 결과를 정하기

사용자: 프리랜서이고 매주 금요일 업무 메모를 정리하는 시간을 줄이고 싶어. 내가 대화에 메모를 붙여줄 거야.

에이전트: 금요일에 붙여준 메모를 정리하는 흐름으로 잡았습니다. 완료 지점을 정하려면 결과 형태가 필요합니다. 결과는 다음 주 할 일 목록과 주간 요약 중 어느 쪽이 필요한가요?

## 3. 순서를 제안하기

사용자: 내가 볼 주간 Markdown 요약. 한 일·다음 할 일·담당·기한이 빠짐없이 있어야 해. 표나 DB는 안 써. 순서는 모르겠어.

에이전트: 추정 초안은 메모 받기 → AI가 항목·담당·기한 정리 → AI 요약 → 사용자 원문 대조입니다. 담당이나 기한이 비면 추측하지 않고 미확인으로 두는 편이 맞겠습니다. 이 순서와 누락 항목을 먼저 묻는 방식으로 진행하면 될까요?

## 4. 충분하면 만들고 종료하기

사용자: 맞아. AI가 빠진 항목을 한 번에 하나씩 물어보고 내가 답하면 갱신해. 원문 항목과 담당·기한이 전부 있어야 끝이야. 도구는 이 대화뿐이고 저장이나 발송은 하지 않아.

에이전트 산출물:

### 주간 정리 워크플로우

- 상태: 설계 완료, 실행 미검증.
- 목적: 프리랜서의 주간 정리 시간 감소. 외부 저장·발송은 제외.
- 시작·입력: 금요일 사용자가 대화에 붙인 업무 메모.
- 결과·완료: 사용자에게 Markdown 주간 요약. 원문 항목, 담당, 기한이 빠짐없이 있고 사용자 대조가 끝나면 완료.
- 환경: 이 대화의 텍스트 처리. 표·DB·외부 연동은 해당 없음.

| 단계 | 담당 | 입력 | 행동 | 출력·다음 조건 |
| --- | --- | --- | --- | --- |
| 메모 전달 | 사용자 | 업무 메모 | 대화에 붙이기 | 원문이 오면 정리 |
| 항목 정리 | AI | 원문 | 한 일·다음 일·담당·기한 구분 | 누락 있으면 보완, 없으면 요약 |
| 누락 보완 | AI·사용자 | 미확인 항목 | AI 질문 하나, 사용자 답을 반영 | 해결 전 해당 항목 보류; 채워지면 요약 |
| 요약 | AI | 정리된 항목 | Markdown으로 작성 | 초안을 사용자에게 전달 |
| 원문 대조 | 사용자 | 원문·초안 | 누락과 담당·기한 확인 | 수정 있으면 해당 단계로, 모두 맞으면 완료 |

미결·다음 질문: 없음. 검증은 실제 메모 한 건과 담당·기한이 빠진 메모 한 건으로 수행할 수 있으나, 이 예시에서는 실제 업무 실행을 하지 않았다.

## 미루거나 충돌한 답

합성 입력: “환불 기준은 A가 7일, B가 14일이라고 했어. 지금 못 정하니 그 결정은 미루고 고객 문의 답변 흐름 초안부터 만들어줘.”

적용 결과: 7일·14일을 모두 충돌로 보존한다. 문의 받기 → 정책 확인 → 답변 초안 → 사용자 검토를 추정으로 제안하며, 환불 결론 작성은 정책 확정 전까지 보류한다. 같은 환불 질문을 곧바로 반복하지 않고 아직 모르는 완료 결과 등 독립적인 다음 결정 하나를 묻는다. 상태는 초안이며 정책 삭제나 자동 발송은 없다.
