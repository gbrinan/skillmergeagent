# <팀 이름> 통합 계약 (CONTRACT)

팀원이 각자 스킬을 만들기 **전에** 팀이 합의해 발급하는 인터페이스 계약이다.
개인은 SKILL.md 본문을 자유롭게 쓰되, 아래 이름들은 문자열 그대로 지킨다.
계약을 고쳐야 할 이유가 생기면 스킬을 고치지 말고 **이 파일을 먼저 고친다** (SSOT).

```contract
# 표 이름은 아래 철자가 정본이다. 띄어쓰기·언더스코어 변형 금지. 확장자가 없는 이름(DB 테이블, 시트 탭)도 된다.
tables:
  표이름.xlsx: 칸1, 칸2, 칸3

# 표마다 기록하는 스킬은 하나뿐이다. 나머지는 읽기만 한다.
writers:
  표이름.xlsx: 기록하는스킬

# 체인 순서. 앞 스킬의 outputs와 뒤 스킬의 inputs는 같은 단어를 쓴다.
# 갈림길이면 경로를 ';'로 나눠 적는다: A -> B -> D; A -> C -> D
chain: 첫스킬 -> 다음스킬 -> 끝스킬

# 스킬끼리 주고받는 페이로드 이름 (정본)
payloads: 이름1, 이름2

# 정지 임계값. 모든 문서에서 이 형식으로만 적는다. 없으면 (해당 없음)
threshold: ±15%

# 사람이 확인하고 멈추는 스킬. 체인 끝뿐 아니라 중간 지점도 콤마로 전부 적는다.
halt_at: 끝스킬
```

## 계약이 정하지 않는 것

- 스킬 본문의 서술 방식, 처리 로직의 세부, 예외 메시지 문구
- 스킬이 속할 사분면(depth/breadth/coil). 통합 시 팀이 배치한다

## 위반 시 처리

`check/check_contract.py`가 제출된 스킬을 계약과 대조해 세 갈래로 나눈다.

| 판정 | 뜻 | 다음 단계 |
| --- | --- | --- |
| 🟢 GREEN | 계약 준수 | 통합 점검기로 진행 |
| 🟡 YELLOW | 이름 표기 어긋남 (기계가 교정안 제시) | 교정안 확인 후 반영, 재검사 |
| 🔴 RED | 팀의 결정이 필요한 충돌 | 팀이 계약 또는 담당을 정하고 재검사 |
